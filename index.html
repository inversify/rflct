The Problem

Why RFLCT?

TypeScript's emitDecoratorMetadata was never part of the TC39 standard and is being removed. RFLCT moves reflection metadata generation from runtime decorator behavior to the build step.

✦

No decorators

Use standard TypeScript syntax. Mark parameters with Reflect<T> — a plain type annotation, not a decorator.

⚡

No emitDecoratorMetadata

Metadata is generated by RFLCT at compile time. No legacy compiler flags needed.

◆

TypeScript 7 ready

Designed around the TypeScript 7 compiler API and the modern tsgo toolchain.

Overview

How RFLCT works

Type information is resolved at build time, not discovered through decorators at runtime.

1

Write TypeScript

Annotate constructor parameters, properties, or method parameters with Reflect<T>.

class Service {
  constructor(repo: Reflect<Repository>) {}
}
2

RFLCT transforms it

At build time, RFLCT analyzes the type annotations and generates metadata calls.

3

Runtime metadata is generated

The output uses the same Reflect.defineMetadata API the ecosystem already understands.

Reflect.defineMetadata(
  "design:paramtypes",
  [{ type: Repository, metadata: {} }],
  Service
);
Get Started

Quick Start

Up and running in under a minute.

1. Install

npm install rflct reflect-metadata

Import reflect-metadata once at your entry point — RFLCT generates metadata compatible with the existing Reflect.defineMetadata / Reflect.getMetadata ecosystem.

import "reflect-metadata";

2. Annotate your code

import { Reflect } from "rflct";

class Service {
  constructor(
    public repository: Reflect<Repository>
  ) {}
}

RFLCT resolves Reflect<Repository> → design:paramtypes → runtime metadata at compile time.

Use Case

Built for dependency injection

Interfaces and type aliases don't exist at runtime. RFLCT gives them stable runtime identities so they can participate in dependency injection.

resolve<T>()

Resolve a TypeScript type to its runtime identity at build time — perfect for DI container bindings.

import { resolve } from "rflct";

container
  .bind(resolve<Shape>())
  .to(Polygon);

Type-only symbols

Interfaces get stable Symbol.for(...) identities that are consistent across packages and builds.

// Generated at build time:
const __RFLCT_Shape =
  Symbol.for(
    "@acme/shapes@1|src/geo.ts|Shape"
  );
Features

Core Features

Everything you need for compile-time reflection metadata.

Reflect<T>

Mark constructor parameters and properties for metadata generation.

resolve<T>()

Resolve a TypeScript type to its runtime identity at build time.

Constructor injection

Generate design:paramtypes metadata for constructor parameters.

Property injection

Generate design:properties and per-property type metadata.

Method parameters

Generate metadata for method parameters on the prototype.

Reflect<T, M>

Attach additional metadata — optionality, constraints, names, tags.

Internals

The five metadata keys

RFLCT generates five well-defined metadata keys — the same design:* convention the ecosystem already understands.

KeyPurpose
design:symbolsGlobal type / runtime identity registry — every class, interface, and type alias
design:paramtypesConstructor, method, and property type metadata
design:propertytypePer-property type metadata with { type, metadata } entries
design:propertiesLists which properties on a class carry Reflect<T> annotations
design:classClass-level metadata via Reflectable<T> in implements clauses

resolve<T>() is an additional transformation that replaces calls with the runtime identity of T at compile time.

Migration

From decorators to RFLCT

Keep the runtime reflection ecosystem. Replace decorator-based metadata generation with compile-time type analysis.

Before — decorators
@injectable()
class UserService {
  constructor(
    private repo: UserRepository
  ) {}
}
After — RFLCT
class UserService {
  constructor(
    private repo: Reflect<UserRepository>
  ) {}
}
Integrations

Works with your build system

Powered by unplugin — one plugin, every build tool.

Vite

import { vitePlugin }
  from "rflct/vite";

export default {
  plugins: [vitePlugin()]
};

Rollup

import { rollupPlugin }
  from "rflct/rollup";

export default {
  plugins: [rollupPlugin()]
};

webpack

const { webpackPlugin }
  = require("rflct/webpack");

module.exports = {
  plugins: [webpackPlugin()]
};

esbuild

import { esbuildPlugin }
  from "rflct/esbuild";

build({
  plugins: [esbuildPlugin()]
});

Don't use a bundler?

RFLCT also provides a CLI for standalone TypeScript 7 / tsgo projects.

npx rflct -p tsconfig.json -o dist

Advanced concepts

Powerful features for complex dependency injection and reflection scenarios.

Multi-injection

Inject arrays of services with elementType metadata for collection injection.

Metadata arguments

Reflect<T, { optional: true }>

Attach arbitrary metadata — optionality, constraints, names — to any annotated parameter or property.

Reflectable<T>

class Svc implements Reflectable {}

Auto-reflect all constructor parameters — no individual Reflect<T> annotations needed.

Type-only symbols

Interfaces and type aliases get stable Symbol.for(...) runtime identities.

Symbol qualification

The package@major|path|Name format ensures cross-package interop guarantees.

Cross-package interop

Symbols from different packages resolve to the same identity when types match.
